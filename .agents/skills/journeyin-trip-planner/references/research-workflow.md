# 资料检索与来源验收规范 (research-workflow.md)

本规范定义 `journeyin-trip-planner` 在行程规划初期的**需求确认、真实互联网检索、小红书深度挖掘、图片搜集与来源证据验收**标准。

---

## 1. 需求确认标准

在启动任何搜索前，必须向用户确认以下核心维度：

### 1.1 必填信息（不可或缺）

- **目的地**：城市名称、特定风景区或跨区域路线（例如“厦门 鼓浪屿”或“川西小环线”）；
- **行程天数与明确日期范围**：JourneyIn 的 `date_range` 字段必须是 `YYYY-MM-DD` 格式（例如 `2026-10-01` 至 `2026-10-05`）。
  - *注意*：若用户只说“玩3天”未给日期，必须主动询问具体日期或出行月份区间，不得随意编造虚构日期。

### 1.2 建议确认与记录的信息

- **出发地与大交通**：出发城市、是否需要将车站/机场作为第 1 天或最后 1 天的规划点；
- **出行同行人与约束**：独行、情侣、亲子、家庭长辈、宠物同行等（直接影响节奏与选点）；
- **偏好重心**：人文古迹、自然风光、地道美食、拍照出片、小众徒步、休闲度假等；
- **预算范围与住宿偏好**：青旅/经济型/高品质酒店/特色民宿，偏好商圈或靠近景区；
- **每日活动节奏**：特种兵式（多点密集）、舒适休闲（每日 2~3 个核心点）、亲子慢节奏；
- **交通出行方式**：公共交通、打车、自驾租车、包车、步行或组合；
- **目标时区**：中国国内目的地默认为 `Asia/Shanghai`。

---

## 2. 搜索前置检查（必须执行）

小红书作为旅行攻略最重要的灵感与一手体验来源，在启动搜索前必须先执行：

```bash
agent-reach doctor --json
```

读取输出中的 `xiaohongshu.active_backend` 字段：
- 若为 `opencli`：使用 `opencli xiaohongshu ...` 命令组；
- 若为 `xiaohongshu-mcp`：使用 `mcporter call 'xiaohongshu...'` 工具接口。

**原则**：开始检索时，向用户明确说明当前正在调用的检索工具与小红书后端，禁止跳过前置体检。

---

## 3. 小红书 5+2 核心深度检索（硬性门槛）

旅行方案不能只凭单一词条草率得出。必须按以下核心维度逐一执行检索，其中 `{X}` 为实际目的地，`{N}` 为天数：

### 3.1 五大基础维度

1. **综合攻略**：

```bash
   opencli xiaohongshu search "{X} 旅游攻略" -f yaml
   # 或 mcporter: xiaohongshu.search_feeds(keyword: "{X} 旅游攻略")
```

2. **必去景点与避坑**：

```bash
   opencli xiaohongshu search "{X} 必去景点" -f yaml
```

3. **地道美食与夜市**：

```bash
   opencli xiaohongshu search "{X} 美食推荐" -f yaml
```

4. **摄影机位与出片打卡**：

```bash
   opencli xiaohongshu search "{X} 拍照打卡" -f yaml
```

5. **行程节奏参考**：

```bash
   opencli xiaohongshu search "{X} {N}天行程" -f yaml
```

### 3.2 两大住宿与住行维度

住宿是行程体验的核心枢纽，跨天规划必须补充检索：

6. **住宿区域选择**：

```bash
   opencli xiaohongshu search "{X} 住宿区域" -f yaml
```

7. **口碑酒店/民宿**：

```bash
   opencli xiaohongshu search "{X} 酒店推荐" -f yaml
```

### 3.3 执行细节与风控要求

- **调用间隔**：每次小红书搜索调用之间保持 **2~3 秒** 间隔，降低防爬与验证码风控；
- **数据留存**：将搜索返回的标题、作者、发布时间、笔记完整 URL 及摘要完整记录到临时研究列表中，作为后续证据引用来源。

---

## 4. 精选笔记正文精读与事实提炼

从搜索列表中挑选 3~5 篇相关度最高的高赞/近期笔记，使用完整 URL 读取笔记正文：

```bash
opencli xiaohongshu note "完整_NOTE_URL" -f yaml
```

### 4.1 提取与分类

阅读正文时必须严格区分：
1. **来源事实 (Source Facts)**：
   - 官方/笔记明示的门票价格、预约方式、开放时间、闭馆日；
   - 实际排队时长、最佳观赏时间段（如日落、亮灯时间）；
   - 地点确切地址、出入口建议（如东门进西门出不走回头路）。
2. **规划推断 (Planning Inferences)**：
   - 规划者建议的游览耗时（如建议游玩 2.5 小时）；
   - 景点间的游览前后衔接关系；
   - 适合早晨还是傍晚的行程编排。

### 4.2 链接与敏感参数清洗

- 小红书分享 URL 中常带有临时追踪参数（如 `xsec_token` 等）；
- 临时参数仅用于当前读取，**禁止将带敏感身份/Cookie 的参数写入长期保存的 Trip**；
- 保存到 JourneyIn 的来源 URL 必须经过清洗，保留安全、公开可访问的 HTTP/HTTPS 链接。

---

## 5. 补充检索与失败降级处理

当小红书出现未登录、网络超时、验证码拦截或特定小众目的地无结果时：

1. **如实记录**：在检索日志中诚实记录小红书检索受阻的状态与原因，严禁捏造“小红书攻略称…”；
2. **启用权威与补充来源**：
   - 官方文旅局官方网站 / 官方公众号发布；
   - 权威旅游平台（马蜂窝、穷游网精选游记）；
   - 百度百科 / 维基百科（基础历史与地理信息）；
   - 全网搜索引擎（Exa / 必应等）搜索最新旅游资讯；
3. **标记来源属性**：所有补充来源均需明确记录平台名称、文章标题与公开 URL。

## 6. 真实图片搜集与嵌入规范

为规划方案中的目的地、每日主题和各规划点搜集可信的配图：

### 6.1 图片搜集渠道

- 优先使用百度百科词条高清图、官方旅游宣传图、维基共享资源 (Wikimedia Commons)；
- 其次使用公共图库或可直接公开访问的高质量图片 URL。

### 6.2 嵌入与格式规范

- **有效直链**：必须是稳定、公开可访问的 `http://` 或 `https://` 图片直链（如 `.jpg`, `.png`, `.webp`）；
- **Alt 说明**：必须包含具体的地点名称和画面内容（如 `![鼓浪屿日光岩俯瞰全岛风景](https://...)`）；
- **来源注明**：在图片 Markdown 下方紧跟图片出处超链接：

```markdown
  ![地点可读描述](https://example.com/photo.jpg)
  图片来源：[来源平台或作者](https://example.com/source)
```

- **无稳定直链时的诚实处理**：
  - **严禁伪造图片 URL**；
  - 找不到稳定公开直链时，在 Markdown 中如实说明“未获取稳定图片直链”，并附带官方或图库参考页面链接。

---

## 7. 资料验收硬门槛 (Gate 0)

在启动地点地理编码与路线设计前，必须完成以下核验：

- [ ] 已完成真实小红书搜索（或已如实记录异常降级流程）；
- [ ] 景点、美食、拍照、住宿、交通全维度均已收集到充分的一手资料；
- [ ] 每一个最终推荐的规划点至少拥有 1 条可溯源的公开来源；
- [ ] 事实（营业时间、门票、规则）与推断（游览时长、动线衔接）界限清晰；
- [ ] 检索记录已完整整理，包含实际关键词、执行平台、时间与结果摘要。

未通过 Gate 0 验收，不得进入地理编码与正式编写阶段！
